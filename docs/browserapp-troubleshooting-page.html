BrowserApp Troubleshooting

Use this page when BrowserApp fetches a page but the result is blank, partial, unreadable, or missing expected links. The BrowserApp intentionally favors bounded text extraction over full browser compatibility.

Fast Triage

  1. Confirm Wi-Fi is connected in NetworkApp.
  2. Retry with a simpler source page or a direct article URL, not a home page.
  3. Check whether the target page depends on heavy JavaScript for core content.
  4. Check whether the page is mainly images/cards/video embeds instead of text.
  5. Try saving the page and reopening it from local storage if the fetch succeeded once.

Expected Limits

ConditionWhat BrowserApp doesWhat to do
JavaScript-rendered pageMay extract little or no contentUse a direct text/article page or create a text-first HTML artifact
Image-heavy layoutText may be incompletePrefer pages with real text in HTML
Complex multi-column siteReading order may collapse poorlyUse a single-column or exported reference page
Interactive controls onlyNo meaningful text resultDo not treat BrowserApp as a full browser

Good Target Pages

  • single-article pages;
  • plain HTML notes and reports;
  • docs or explainers with one-column structure;
  • self-contained HTML files exported specifically for Cardputer.

Recommended Authoring Pattern

If a page is meant to be read on Cardputer, prefer the local contract in docs/html-artifact-contract.md and use the single-file templates under templates/html/.

  • no required JavaScript;
  • semantic headings and lists;
  • meaningful links in text form;
  • one-column reading flow;
  • no hidden critical content.

If The Fetch Works But The Result Looks Wrong

  • Assume extraction succeeded but layout semantics were weak.
  • Use a cleaner source page if available.
  • Export a dedicated troubleshooting or reference artifact instead of relying on the live site.
